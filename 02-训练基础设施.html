训练基础设施

如果算法决定了「训什么」，训练基础设施（AI Infra）决定的就是能不能塞进显存、多卡会不会互相干等、机器坏一张卡会不会全盘白跑。

检验一套训练基建合不合格，标准很实在：同一份训练作业，换个队列、换套并行切分，它的 MFU（模型算力利用率）、每张卡每秒处理的 token 数、以及损失下降曲线，都还落在极小的误差范围内。

下面把提问里的「现存优化」还原为显存优化，「算自由化」展开为算力池化、作业可迁移与算子加速。

集群

一台合格的训练节点，不是只看插了几张 GPU，而是三件事配平：

  1. 加速卡与机内高速互联：H100 / H200 / B200 或同档算力卡，同一台机器内部用 NVLink / NVSwitch 连起来（带宽通常在数百 GB/s 级），专门伺候通信最密集的张量并行。
  2. 机间 RDMA 网络：机器和机器之间用 InfiniBand（NDR / XDR）或无损 RoCEv2，并且打开 GPUDirect RDMA——让网卡直接读写 GPU 显存，数据不用先绕回 CPU 内存兜一圈。
  3. CPU 与存储：足够多的 CPU 核负责实时解码和拼装数据，节点本地配 NVMe 固态盘做检查点缓存；底层挂并行文件系统（Lustre、GPFS、3FS 等）。存储带宽的硬指标就一条：全量模型加优化器状态的检查点，必须在几分钟内写完，否则存盘时间会把训练步时拖垮。

网络拓扑一般按轨优化（Rail-Optimized）设计：同一个并行通信组尽量落在同一台叶交换机下面，少跨脊交换机绕远路。

调度

训练作业和普通网页服务完全不同：一个 64 卡的 3D 并行训练作业，少一张卡都没法开工。所以调度器必须支持成组调度（Gang Scheduling）——要么 64 张卡同时就位一起拉起，要么就先排队，绝不能先占着 60 张卡干等剩下 4 张。

同时还要做到：整节点独占、GPU 和对应 CPU NUMA 节点及网卡就近绑定、把同批次同型号的机器分在一组、某台机器掉线后自动剔除坏节点并从最近一次检查点重新拉起。

显存

训练时显存里到底装了什么？主要有四块：模型权重、梯度、优化器状态（Adam 要存一阶和二阶动量，占大头）、前向激活值（留着给反向传播算梯度用）。

拆解显存墙，工程上固定按下面这个顺序动手：

  1. 混合精度（BF16 / FP8）：权重和激活平时用 BF16 算，省一半显存且不容易溢出；优化器里的主权重和累加仍然保留 FP32，保住微小更新不丢失。支持 FP8 的卡可以用 Transformer Engine 在线性层前向反向进一步提速省显存。
  2. 激活检查点（Activation Checkpointing / 重计算）：前向传播时不把每一层的中间激活都傻傻存下来，只存几个关键节点（或者只存注意力层里算起来最费劲的那部分，叫选择性重计算），反向传播需要用到时再当场重算一遍——拿一点点计算时间，换回大把显存。
  3. ZeRO 与 FSDP（把冗余状态切开）：普通数据并行里，每张卡都完整复制了一份权重、梯度和优化器状态，太浪费。ZeRO 的三档切法非常直观：ZeRO-1 只把优化器状态按卡切开；ZeRO-2 连梯度也一起切开；ZeRO-3（对应 PyTorch 的 FSDP / FSDP2）连模型权重本身也切开，哪一层要算了再临时从别的卡拼回来，算完立刻释放。
  4. 序列并行（SP）与上下文并行（CP）：当上下文拉长到几万甚至几十万词时，单条样本的激活值就能把显存撑爆。序列并行把 LayerNorm、Dropout 等沿着序列长度维度切到不同卡上；上下文并行把注意力本身也沿序列维度切开。
  5. 专家并行（EP）：MoE 模型里不同专家分到不同卡上，token 通过 all-to-all 通信去找对应的专家计算。
  6. CPU / NVMe 卸载（Offload）：实在塞不下时，把平时不用的优化器状态甚至权重挪到主机内存或 NVMe 硬盘里。注意这能救命，但 PCIe 带宽远慢于显存，吞吐会掉一截，能不卸载尽量不卸载。

通信

多卡训练最怕「卡在等网卡」。通信优化的核心就一句话：把通信藏进计算里（Overlap），并且每次尽量传整块大消息，少发零碎小消息。

  • 集合通信与桶合并：底层靠 NVIDIA/nccl。数据并行反向传播时，后一层梯度刚算完，立刻打进固定大小的通信桶（Bucket）开始做 All-Reduce，同时 GPU 继续往前算前一层的梯度，两边同时干活。
  • 并行位置摆放：张量并行（TP）每一层都要做 All-Reduce 或 All-Gather + Reduce-Scatter，不能藏，必须放在机内 NVLink 里；流水线并行（PP）只传层间激活，通信量最小，适合跨机器；数据并行（DP）可以做通信重叠，也适合跨机器。
  • 流水线消除气泡：把模型按层切成几段分给不同卡时，如果等一整个批次前向跑完再跑反向，大部分卡都在空等（这叫流水线气泡）。工程上用 1F1B（一前向一反向交替） 和交错式虚拟流水线把气泡压小；更激进的 Zero Bubble（零气泡流水线） 把反向拆成「对输入的梯度」和「对权重的梯度」两步，拿后者去填补空隙，几乎可以把气泡消干净。

长序列训练时，单张卡放不下完整序列，有两种正交的切法：

  • Ring Attention：把长序列切成几段分给不同卡，计算注意力时，Query 留在本地，Key 和 Value 像击鼓传花一样在卡间按环状传一圈，边传边算，把通信完全藏进注意力计算里。论文：Ring Attention with Blockwise Transformers for Near-Infinite Context页内读 PDF arXiv ↗，参考实现：zhuzilin/ring-flash-attention。
  • DeepSpeed Ulysses：在做注意力前，用一次 All-to-All 通信把「按序列切分」瞬间转置成「按注意力头（Head）切分」，每张卡拿齐完整序列的几个头独立算完注意力，再 All-to-All 转回来。通信量小、实现干净。论文：DeepSpeed Ulysses页内读 PDF arXiv ↗。

算力自由化

什么叫「算力自由化」？就是训练作业不再死死绑在某几台固定机器、某一种固定并行度、或者某一个手搭环境上。今天给 32 张卡能跑，明天调度器挪到另一个池子给 64 张卡，改个配置接着检查点就能继续跑。要做到这件事，靠四块基建：

  1. 统一作业描述：数据版本、检查点路径、并行切分、容器镜像哈希、队列优先级全写在一份标准配置里，底层不管是 Slurm 还是 K8s 都能一键拉起（例如用 SkyPilot 或内部统一提交器）。
  2. 资源池化与弹性配额：业务团队申请的是「GPU 小时数」和优先级，高优任务来了可以抢占低优实验，闲时算力自动借给批量采样或合成数据任务。
  3. 分布式检查点可重切分（Resharding）：以前用 TP=4, PP=2 存下的检查点，换机器后想改成 TP=8, PP=1 就加载不了。现在用 PyTorch DCP（Distributed Checkpoint）或 Megatron 分布式检查点，存盘时保存逻辑张量坐标，加载时自动按新的并行度重新切分；Megatron-Bridge 则专门负责 Megatron 格式与 Hugging Face 格式双向无损互转。
  4. 异步检查点与秒级恢复：先把检查点飞快拷到主机内存，训练进程立刻继续跑下一步，后台线程慢慢往分布式存储里写。作业一旦被抢占或遇到机器故障，重新拉起时只丢最后几分钟进度。

注意：同一个 3D 并行作业内部，不建议把不同代、不同显存的卡混在一起跑（木桶效应会让快卡干等慢卡）；算力池化真正的落点是「同代卡池内任意成组、不同阶段的训练/采样/评测按需分到最合适的卡池」。

算子与吞吐

看集群跑得快不快，不要看 nvidia-smi 里那个 GPU-Util 99%——哪怕只有 1 个线程在死循环等显存，那个数字也是 100%。真正硬核的北向指标是 MFU（Model FLOPs Utilization，模型算力利用率）：模型理论上每一步最少要算的浮点运算次数，除以显卡标称峰值算力。这个口径由 PaLM 论文确立：PaLM: Scaling Language Modeling with Pathways页内读 PDF arXiv ↗。

要把吞吐和 MFU 榨出来，核心是解决显存带宽瓶颈（Memory-Bound）：GPU 算乘法极快，但把中间结果从高带宽显存（HBM）搬进片上高速缓存（SRAM）再搬回去极慢。

  • FlashAttention 系列：以前算注意力，要把巨大的 N × N 注意力矩阵写回 HBM 再读出来算 Softmax，全卡在读写显存上。FlashAttention 把输入分块放进片上 SRAM，利用在线 Softmax 技巧在片上一次性算完，根本不把中间大矩阵写回显存；FA-2 优化了线程块并行划分；FA-3 进一步用上了 Hopper 架构的异步指令与 FP8 低精度。
  • 算子融合与编译：把 RMSNorm、RoPE、SwiGLU 激活、交叉熵损失里的多次零碎显存读写融合成一个内核（用 Triton 手写或开 torch.compile），再用 CUDA Graph 把一长串内核发射打包成一次提交，省掉 CPU 逐个唤醒 GPU 的开销。
  • FP8 混合精度：在支持的显卡上用 Transformer Engine 开启 FP8 矩阵乘，吞吐能再上一个台阶，但要盯紧损失曲线有没有因为精度变低而跑偏。

日常调优时，把每一步耗时拆成七段看：前向、反向、优化器更新、数据加载、通信等待、写检查点、RL 采样。用 Nsight Systems 看通信和计算有没有严丝合缝叠在一起，用 PyTorch Profiler 抓哪个算子在拖后腿。每次升级驱动、CUDA、NCCL 或训练镜像，都先跑一遍固定的「黄金基准配置」，MFU 一掉立刻拦截。

强化学习运行时

跑 GRPO、DAPO、PPO 这类在线后训练时，最大的性能瓶颈根本不在反向传播，而在自己跟自己对话生成答案的那一步（Rollout 采样）——往往 70% 以上的时间都花在等模型把几千字的长思维链一个词一个词蹦出来。

所以一套现代 RL 后训练系统，标准架构是这五件套协同：

  1. 训练端（Actor / Reference）：用 FSDP2 或 Megatron 切分，专门负责算对数概率和反向传播更新权重。
  2. 推理采样端（Rollout Engine）：专门用 vLLM 或 SGLang 跑连续批处理（Continuous Batching）和 PagedAttention；对同一道题采样 16 条回答时，打开前缀缓存（Prefix Caching / RadixAttention），提示词的 KV Cache 只算一次。
  3. 毫秒级权重同步：每训完一步，策略权重变了，得立刻把新权重从训练态的并行切分，通过 NCCL 广播或同机显存共享（IPC）重新拼好刷进 vLLM / SGLang 里，绝不能傻傻写硬盘再重读。
  4. 独立验证器服务（Verifier / Sandbox）：跑代码单测、数学符号化简、编译器检查全部丢给独立的 CPU 容器池并发执行，绝不让慢吞吞的沙箱把昂贵的 GPU 挂起干等。
  5. 长尾缓解与轨迹缓存：同一批里 15 条回答 2 秒写完，偏偏有 1 条写了三万字还在磨蹭，整批卡就得陪着等。工程上通过偏异步采样、分段截断续写、以及把已打分轨迹落盘缓存（崩了重启不重采）来消掉这个长尾。

HybridFlow（即开源的 verl） 把这套复杂的跨集群数据流抽象成了单控制器调度 + 多进程组协同，是目前最清晰的工业级范本。

观测与故障

规模一上百卡千卡，硬件出小毛病是家常便饭。靠人盯日志根本忙不过来，必须配齐四类自动巡检：

  • GPU 硬件健康：用 NVIDIA/DCGM 持续采集显存 ECC 纠错计数、温度降频、NVLink 错误和 Xid 硬件报错。
  • 网络健康：盯住网卡丢包、PFC 死锁、RDMA 重传计数。
  • 慢节点（Straggler）抓捕：所有卡在集合通信前都要互相等待，只要有一张卡因为散热或网卡降速慢了 20%，整个千卡集群就跟着慢 20%。对比各 Rank 的计算耗时与入队时间差，就能把拖后腿的那台机器揪出来。
  • 通信超时定位到具体 Rank：NCCL 一旦超时报错，系统要能直接指出是哪两个 Rank 之间握手卡死，自动隔离机器并从异步检查点重拉作业，而不是让人对着几千行一样的报错堆栈发呆。
